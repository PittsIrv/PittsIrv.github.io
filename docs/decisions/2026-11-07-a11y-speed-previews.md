# Accessibility, speed and link previews (T-0048)

## Intent
Measure every page with free tools, fix what fails, and give every page a title, description and a preview image for link unfurls. Measure: Lighthouse accessibility, best practices and SEO at 95 or more and axe with 0 serious or critical on each page.

## Baseline and result
Local production build (`astro preview`), Lighthouse 12 mobile and desktop plus axe-core 4 (WCAG 2.0/2.1 A and AA, best-practice), headless Chrome. The ticket lists `/research`; no such page exists, so `/work` was audited in its place. The two content pages (a poem, an article) were added.

Performance was already 100 on every page, both modes. Layout shift was at most 0.002 and mobile largest contentful paint 1.2 to 1.5 s before and after.

**Measuring artifact.** The first axe pass flagged 8 contrast hits on `/work` and 5 nav links on `/personal` because it sampled the nav while its fade-in animation was still partly transparent. After 2.5 s the same elements pass (muted text on the page background is 5.98:1). The script now waits for animations to finish. Only the 12 real failures are counted above.

## Decisions
- **Faint grey text.** Claude, small. The "Updated" line and the sports levels on `/personal` used the framework's lightest grey (2.53:1). Added a `--faint` colour (#606c84, about 5.2:1 on the page background) and mapped the faint text class to it, next to the existing rule that maps the muted classes. One CSS rule, no page edits, so the hierarchy between name and level stays visible.
- **Poker page headings.** Claude, small. The page jumped from the title to level-3 headings. Section headings are now level 2 and variant names level 3. Classes are unchanged, so nothing looks different; the one CSS selector that targeted the old tag was updated.
- **Preview images.** Claude, small. 10 PNGs (1200x630) in `public/og/`, one per page, drawn from the site's own serif font, paper and ink colours and accent bar. Text is the page title only, plus the home page's existing "AI Systems Engineer". Generated by `scripts/generate-og.mjs` with local Chrome and no new dependency; the PNGs are committed because the build should not need Chrome.
- **Layout derives the image from the path.** Claude, small. `/personal/poker` maps to `og/personal-poker.png`. A new page with no image fails the build (below), so a missing preview cannot ship.
- **Twitter card now `summary_large_image`.** Claude, small, with image width, height and alt tags.
- **Poem and article descriptions.** Claude, small. They fell back to the generic site description. They now use the first 155 characters of the page's own text. No new sentences were written.
- **Build check.** Claude, small. `scripts/check-previews.mjs` runs in `npm run build` after the CSP check and fails when a built page lacks a title, description, or an `og:image` and `twitter:image` pointing to a file in the build.
- **CSP.** Unchanged. The policy builder and its check were not edited; the image URLs are meta tags, not loaded by the page.
- **Pages with existing descriptions.** Left as written. The Work description already names two labs; that text predates this ticket and was not edited.

## Intuitions and rejected alternatives
- Rejected: preloading the serif font file. Performance is 100 and layout shift near zero, so there is nothing to win, and it adds a build-hash import.
- Rejected: generating images at build time. Needs Chrome in the deploy, which the GitHub Actions flow does not have. Static files are simpler and reviewable.
- Rejected: per-page images that carry descriptive sentences. That would be new copy in Mingxi's voice, which the ticket forbids.
- Not done: real unfurl test in Slack or iMessage. Needs a live URL; the tags and files are checked in the build, and the live URL is checked after deploy.

## How to verify
- Run `npm run build`; it prints "Preview check: 10 pages have a title, description and preview image".
- Open `/personal`: the "Updated" line and the sports levels are a slightly darker grey than before. Open `/personal/poker`: nothing looks different.
- Open `/og/home.png` and `/og/personal-poker.png` on the site: a white card with the page title in the site's serif.
- Paste a page link into a chat app: a large preview card appears (after deploy; some apps cache old unfurls).

## Revisit when
- A page, poem or article is added: run `node scripts/generate-og.mjs` and commit the new PNG, or the build fails on purpose.
- The site colours or font change: regenerate the images.
- Never for the contrast and heading fixes; they are measured and enforced by the audit.

## Independent review — 2026-11-07 (gemini-3.1-pro-preview, single pass, middle tier)
- Excerpt keeps URLs from Markdown links → agree; fixed. The helper moved to `src/lib/excerpt.ts`, strips `[text](url)` to its text, and is shared by poems and articles (the inline copy also tripped the Astro compiler once the pattern grew).
- Checker depends on meta attribute order → agree; fixed. It now reads every attribute of each meta tag, so order no longer matters. Checked by deleting a preview file from a copy of the build: the check fails and names the page.
- Image script skips nested content folders → disagree. Collection slugs here are flat; a nested file would also fail the preview check, so it cannot ship silently.
- Subpath deployment breaks the file lookup → disagree. The site is a user site with no `base`; the lookup is correct for it and would be revisited with any `base`.
- Script assumes macOS Chrome path → agree in part. The header already documents `CHROME_PATH`; no change.
- Committed PNGs bloat the repo → disagree. 10 files, about 220 KB in total; satori or resvg would add dependencies for a one-off. Revisit if the page count passes about 50.
- Parse the built HTML with cheerio → disagree. The attribute-order fix covers the failure; a dependency is not warranted.
- Does the body include frontmatter? → no; the built descriptions show clean text.
- Documentation gap (manual regeneration step) → covered by "Revisit when" above and the script header.
Verdict: Ship with fixes. Action taken: both fixes made in this PR.
